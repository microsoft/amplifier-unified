# Task capacity and consumption budgets

`capacity.read`, `capacity.set`, and `capacity.quota` are the same actions used by the Limits & context panel and `app_control`. Agent actions are bound to the calling conversation. Reads do not select a conversation, alter its draft, start a model call, or infer permission.

## Usage ownership and accuracy

The existing durable execution projection remains the only usage store. Each provider completion has an opaque call ID, a producer/process identity, a monotonic revision, provider/model identity, timestamps and allowlisted public usage. A later cumulative snapshot replaces that call's receipt. Duplicate or older revisions cannot add a charge or roll a corrected value backward. Removed costs become unknown, not zero. Tool and worker aggregate summaries never contribute another copy of their children's usage.

The view includes the root and descendants actually observed in its execution tree/worker registry; matching workspace, title, or a caller-supplied ID does not establish ancestry. Unbound records are excluded and counted visibly. Historical edits transfer removed model and worker receipts into `execution.retiredUsageNodes`, outside the current visible execution tree, so editing text cannot erase incurred usage. Receipts are metadata, not model prompts, responses, reasoning content or a second transcript. Provider-reported reasoning *counts* may be included.

Every metric states its unit, known/pending/unknown call counts and availability. A null value means no known value; known subtotals with missing receipts are partial. Cost estimates remain attributed estimates and require an explicit choice to count toward a cost limit. No host pricing table or assumed token-to-dollar conversion is used. Tokens are cumulative billed/reported work, not remaining context-window capacity.

`capacity.read {sessionId, offset?, limit?}` computes totals from all receipts and returns bounded receipt pages (100 default, 500 maximum), with `nextOffset`. Provider/model breakdowns retain separate unknown fields. Snapshot timestamps are observations, not a guarantee that all external usage has arrived.

## Budget admission and persistence

`capacity.set` takes `expectedRevision` and the action's stable command ID. It accepts `enabled`, `maxTotalTokens`, `maxCostUsd`, `warningFraction`, `unknownPolicy` (`pause` or `allow`), and `includeEstimatedCost`. At least one positive limit is required when enabled. Limits are cumulative over this conversation's recorded lifetime, including previous objectives and edited history. They are not reset by starting a new goal. Receipts include origin and the task ID/revision present when edited.

Policy, edit receipts and the most recent denied admission live in the existing `control-state.json`; the runtime control owner is the sole writer. Edits work while a response is running and take effect on subsequent admission. No second goal controller or scheduler is introduced.

Before each supported provider `complete` call or `stream` iterator, the existing observation wrapper asks the host to check the latest saved budget and execution receipts. The host persists the call intent under the same execution ID before admitting it, with admission time and the exact budget revision. Mutable providers retain their instance; immutable providers use a transparent wrapper that forwards all other optional provider methods. Repeating an admitted ID is rejected, never replayed. The wrapper runs after provider selection/native adaptation and before surface delivery. Underlying SDK retries within a call are not separately billed unless the provider reports them. Streaming usage chunks and final hooks replace the same cumulative receipt; iterator cancellation/close retains an interrupted receipt and closes the underlying iterator. A provider implementing one protocol through the other gets one admission, with context scoped to actual iterator advancement.

A reached limit or disallowed unknown settled usage pauses future model calls and goal continuation. It does **not** stop or undo calls, tool effects, delegated work or remote operations already in flight. Concurrent admitted requests may finish above the configured limit. No reservation estimates are invented. A host restart or a new runtime producer marks previously unfinished observed calls `outcome_unknown`; its original receipt is preserved and not resubmitted. Explicitly editing the budget clears the recorded denial, but the next admission rechecks consumption and unknowns. Budget editing never sends input or resumes a separately paused task. Latest objective corrections and dependency/artifact references stay with the existing task controller.

The finite admission scope is the main and observed child provider `complete`/`stream` boundaries, plus explicit native compaction through the same observed-call gate. Realtime audio requests, direct tool invocations, independent external MCP/tool-owned AI, and another application's account use are not forcibly stopped by this policy. Recorded voice usage can contribute to observed totals, but this feature does not claim account-wide billing completeness or a financial hard cap. Historical sessions without usage telemetry remain incomplete. Providers that bypass both standard invocation boundaries are outside enforcement.

## Provider-owned quota reads

A mounted provider may offer an optional read-only `get_usage_limits()` method, sync or async, returning `{"windows":[{"name":...,"unit":...,"limit":...,"used":...,"remaining":...,"resetsAt":...}]}`. Numeric fields must be finite and nonnegative; `resetsAt` is Unix UTC seconds. The host allowlists these fields, records observation time and source, and does not expose arbitrary account metadata. Missing values remain null. No windows means unknown; missing capability means unsupported; a failed/timed-out read means unavailable. An unsupported provider is never shown as having zero remaining quota.

This capability belongs to the provider adapter. No provider's credentials, undocumented billing endpoint, or account reset behavior is guessed. This slice does not introduce a provider quota adapter where none exists. Quota/reset reads are distinct from task consumption and never purchase or redeem credits.
