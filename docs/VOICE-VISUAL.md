# Explicit computer context in chat and voice

Open **Chat controls** with the composer sliders, then select **Computer use**. The controls are hidden until the panel is opened. Ordinary text chat and a connected voice call can use snapshots of a window, tab, or display selected by its browser owner. The browser must support `getDisplayMedia` and `ImageCapture` (or fresh video frame callbacks) on localhost or HTTPS. The source picker requires a direct user click. The optional local macOS adapter also supports explicitly selected native foreground window identity and pixels. Neither adapter grants desktop control or background monitoring; accessibility text is not supplied.

**Choose screen source** grants explicit UI/agent snapshots for up to fifteen minutes to this conversation in this browser. Text and voice share that permission: starting or ending a call does not discard the selected source. Switching chats, disconnecting, page exit, track end, expiry, and explicit revocation end sharing. A new source must be chosen after reconnect; grants are never restored after host restart. The UI states the scope before the picker opens and names the browser-reported source. A **Sharing active** indicator with **Stop sharing** stays visible outside Chat controls, including when the panel is closed. Stop releases the local browser stream immediately and revokes server access through the shared action. Each snapshot requires a separate action; video stays local between actions and no periodic images are sent.

Agents open and reveal the same panel through `view.update`, for example:

```json
{"patch":{"panel":"runtime","runtimeDraft":{"section":"screen-source"}}}
```

Known sections are `overview`, `direction`, `limits`, `tools`, `computer`, `screen-source`, `desktop-host`, and `capture`. A section selects its tab, opens the panel, scrolls it into view and focuses it. Each reveal increments a server revision, including repeated requests for the same section. `runtimeDraft.tab` can also select a tab without granting access. Navigation merges the existing controls draft. For agent panel and computer actions, use `canvasContext.connectedClientIds` from `get_state`. A saved browser view is not a live client: disconnected explicit or inherited targets are rejected. App controls default to the browser that submitted the active inputs. Inspect `computerVisual` independently of voice status. Screen actions require one authoritative connected input origin; if it is missing or mixed, ask for a fresh input from the intended browser. Explicit ordinary navigation or Canvas targeting does not transfer screen consent. Integrations without input provenance retain the existing explicit connected-client contract. Selection is checked again before committing navigation. Existing Canvas catalog/readback retains saved view records, and this rule does not change its targeting contract. Agents cannot target a client displaying another conversation. Opening or revealing the controls never invokes a picker, native preflight, or capture. Only the user can choose/grant a source or satisfy browser/OS consent.

Conversation actions are `computer.visual.status`, `computer.visual.capture`, and `computer.visual.revoke`, scoped to `sessionId` and the originating browser client. They work in both text and voice. The older `voice.visual.*` endpoints remain for existing call-scoped clients and require their exact call identity; the current UI uses conversation grants. Agents may act only in their calling conversation. Source selection and image callbacks are browser-owner routes outside the agent action catalog. Browser, conversation, source grant, capture nonce, and freshness are revalidated when evidence arrives and when a provider request uses it. Only one capture may be pending. Captures have a ten-second response deadline and two-second rate limit. Stable command IDs prevent capture replay after a lost response or restart; an interrupted request stays unconfirmed.

Each image is a PNG at most 1280 pixels per side and 500 KB, with capture/receipt times, source label/kind, dimensions, and SHA-256. Source names and pixels remain untrusted reference data. The host has no independent native verification of the browser-reported source. Pixels use the existing private attachment store and saved conversation reference, preserving ordinary attachment export/inspection. Capturing never selects a conversation, changes its draft, or starts model work.

An explicit agent capture returns metadata, then supplies typed image content at the existing `SurfaceProvider` boundary while the exact result is retained, the conversation/client or call/source still matches, the capture is under thirty seconds old, and the provider advertises image support. Lack of image support or stale permission produces a text notice that no pixels were delivered. Capture receipts do not prove the model saw an image. A UI capture is consumed once by the next input within thirty seconds through the normal attachment input encoder: a text or spoken input from the same browser and conversation. Older call grants remain limited to the spoken call input. It is not automatically sent to the voice provider itself, to unrelated text requests, or to future turns after compaction/restart.

Saved snapshots remain historical attachments after permission ends. Grant/capture availability is memory-only. Existing mutable computer/browser tools remain separate optional capabilities with their own permissions. This implementation neither routes around their safety stops nor claims their native OS support.

Validation: backend ownership, exact receipt, source replacement, late response, permission/error, restart/no-replay and typed image tests; browser unit cleanup/reconnect tests; `npm run test:voice-visual-browser` uses production UI/routes with explicitly synthetic voice signaling and a real canvas media stream. It proves frame serialization and UI/agent paths, not physical display permissions, live provider audio, or native OS capture.

The provider boundary revalidates call/source permission after any cached budget calculation and before transport. Revoking the conversation source between budget preparation and send removes the cached image; ending a legacy call-scoped grant does so as well. New input context expires the agent's image receipt; an old capture cannot follow an unrelated new request merely because its tool output is still in history.

## Optional native desktop source

Install the `native-desktop` extra explicitly in the **serving app environment** to add the computer-use module library. A conversation worker installation cannot supply the host helper's imports. Its declaration follows the consumed upstream library at `@main`; qualify the app and optional dependency together before replacing a managed installation. Installing the extra never starts a capture or requests an OS permission. [Desktop & browser setup](DESKTOP-READINESS.md) reports the exact host interpreter and separate mounted conversation tools without starting a runtime.

In the Computer use tab, **Check desktop host** runs only a read-only availability/Screen Recording preflight. It identifies the server host using the existing Foundation owner hostname (`identitySource=foundation-owner-hostname`), plus a distinct running instance ID. A hostname is local and restart-stable only while the name remains unchanged, not a hardware or globally unique identifier. The UI explicitly says this may differ from the browser device. **Allow foreground snapshots from … for this chat in this browser** grants the named host; it does not capture. **Capture screen**, or the same scoped agent action, requests one new observation. No client-selected hostname can redirect capture to another device.

A fixed helper runs in a fresh isolated Python process with only `status` or `capture`, a three/six-second deadline, bounded output and kill/reap on cancellation. The library uses the existing Mac backend; its utility fallback is disabled to avoid leaving temporary pixels on hard cancellation. The helper cannot grant OS permission, send input, read target configuration, or clear a computer-tool halt. Revocation, conversation/browser scope changes, source replacement and host restart discard late pixels. Legacy call-scoped grants also end with their call. Browser image callbacks cannot submit native evidence. Native receipts add the observed window/application/bounds and preserve the same saved PNG, digest and typed image delivery path. App/window names are untrusted source data.

macOS Screen Recording must already be granted to the executing host application. An absent optional dependency, unsupported OS, unavailable desktop, missing/unknown permission, changed foreground window, clipped image, oversized result or deadline returns an unavailable/error outcome. There is no automatic permission prompt or whole-desktop retry. Real OS permission/capture and physical audio remain user-mediated acceptance steps; automated browser acceptance uses a synthetic native backend.

Provider errors with `computer_result_not_image` now retain allowlisted call identity and result kind in conversation diagnostics. The provider-owned later-user recovery projection represents an old failed native call/result as bounded untrusted history only after a subsequent real user message; it never edits the canonical transcript, invents pixels, replays the action, or clears any safety halt. The current failed turn still fails closed. Explicit recovery copies remain available separately.
