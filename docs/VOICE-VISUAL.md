# Explicit screen context during voice

A connected voice call can use snapshots of a window, tab, or display selected by its browser owner. The browser must support `getDisplayMedia` and fresh video frame callbacks on localhost or HTTPS. The source picker requires a direct user click. The optional local macOS adapter also supports explicitly selected native foreground window identity and pixels. Neither adapter grants desktop control or background monitoring; accessibility text is not supplied.

**Choose screen source** grants explicit UI/agent snapshots from that source for this call for up to fifteen minutes. The UI states the scope before the picker opens, names the browser-reported source, shows capture time, and offers **Stop screen sharing**. Each snapshot requires a separate action. Video remains local between actions; no periodic images are sent. Reconnect, call change/end/error, page exit, track end, and explicit revocation discard local permission. A new source must be chosen after reconnect; grants are never restored after host restart.

The shared actions are `voice.visual.status`, `voice.visual.capture`, and `voice.visual.revoke`, each requiring exact `sessionId` and `callId`. Agents may act only in their calling conversation. The grant and image callbacks are browser-owner routes, outside the agent action catalog. Call owner, source grant, capture nonce, freshness, and active-call status are revalidated when evidence arrives and when a provider request uses it. Only one capture may be pending. Captures have a ten-second response deadline and two-second rate limit. Stable command IDs prevent capture replay after a lost response or restart; an interrupted request stays unconfirmed.

Each image is a PNG at most 1280 pixels per side and 500 KB, with capture/receipt times, source label/kind, dimensions, and SHA-256. Source names and pixels remain untrusted reference data. The host has no independent native verification of the browser-reported source. Pixels use the existing private attachment store and saved conversation reference, preserving ordinary attachment export/inspection. Capturing never selects a conversation, changes its draft, or starts model work.

An explicit agent capture returns metadata, then supplies typed image content at the existing `SurfaceProvider` boundary while the exact result is retained, the call/source still matches, the capture is under thirty seconds old, and the provider advertises image support. Lack of image support or stale permission produces a text notice that no pixels were delivered. Capture receipts do not prove the model saw an image. A UI capture is consumed once by the next spoken input within thirty seconds through the normal attachment input encoder. It is not automatically sent to the voice provider itself, to unrelated text requests, or to future turns after compaction/restart.

Saved snapshots remain historical attachments after permission ends. Grant/capture availability is memory-only. Existing mutable computer/browser tools remain separate optional capabilities with their own permissions. This implementation neither routes around their safety stops nor claims their native OS support.

Validation: backend ownership, exact receipt, source replacement, late response, permission/error, restart/no-replay and typed image tests; browser unit cleanup/reconnect tests; `npm run test:voice-visual-browser` uses production UI/routes with explicitly synthetic voice signaling and a real canvas media stream. It proves frame serialization and UI/agent paths, not physical display permissions, live provider audio, or native OS capture.

The provider boundary revalidates call/source permission after any cached budget calculation and before transport. Ending the call between budget preparation and send removes the cached image. New input context expires the agent's image receipt; an old capture cannot follow an unrelated new request merely because its tool output is still in history.

## Optional native desktop source

Install the `native-desktop` extra explicitly in the **serving app environment** to add the computer-use module library. A conversation worker installation cannot supply the host helper's imports. Its declaration follows the consumed upstream library at `@main`; qualify the app and optional dependency together before replacing a managed installation. Installing the extra never starts a capture or requests an OS permission. [Desktop & browser setup](DESKTOP-READINESS.md) reports the exact host interpreter and separate mounted conversation tools without starting a runtime.

During a connected call, **Check desktop host** runs only a read-only availability/Screen Recording preflight. It identifies the server host using the existing Foundation owner hostname (`identitySource=foundation-owner-hostname`), plus a distinct running instance ID. A hostname is local and restart-stable only while the name remains unchanged, not a hardware or globally unique identifier. The UI explicitly says this may differ from the browser device. **Allow foreground snapshots from … for this call** grants the named host; it does not capture. **Capture screen**, or the same scoped agent action, requests one new observation. No client-selected hostname can redirect capture to another device.

A fixed helper runs in a fresh isolated Python process with only `status` or `capture`, a three/six-second deadline, bounded output and kill/reap on cancellation. The library uses the existing Mac backend; its utility fallback is disabled to avoid leaving temporary pixels on hard cancellation. The helper cannot grant OS permission, send input, read target configuration, or clear a computer-tool halt. Revocation, call end, source replacement and host restart discard late pixels. Browser image callbacks cannot submit native evidence. Native receipts add the observed window/application/bounds and preserve the same saved PNG, digest and typed image delivery path. App/window names are untrusted source data.

macOS Screen Recording must already be granted to the executing host application. An absent optional dependency, unsupported OS, unavailable desktop, missing/unknown permission, changed foreground window, clipped image, oversized result or deadline returns an unavailable/error outcome. There is no automatic permission prompt or whole-desktop retry. Real OS permission/capture and physical audio remain user-mediated acceptance steps; automated browser acceptance uses a synthetic native backend.

Provider errors with `computer_result_not_image` now retain allowlisted call identity and result kind in conversation diagnostics. The provider-owned later-user recovery projection represents an old failed native call/result as bounded untrusted history only after a subsequent real user message; it never edits the canonical transcript, invents pixels, replays the action, or clears any safety halt. The current failed turn still fails closed. Explicit recovery copies remain available separately.
