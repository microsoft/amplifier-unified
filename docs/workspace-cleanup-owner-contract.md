# Reviewed workspace file removal

The product coordinator holds the existing recovery maintenance fence across all
configured owners. The workspace owner contributes registered folder identities,
their revision, and recorded external-resource status. The Host contributes a
bounded metadata-only census of indexed and Host-known conversations, including
hidden and archived entries. The catalog supplies index facts only; it does not
claim native-writer ownership. Native independently protects its history and
application roots and holds native-home and selected-history writer leases.

Preview and removal use the same complete census and file-inventory revision.
Removal requires the reviewed folder path. Native alone renames and removes the
folder, preserving canonical history. Its original command receipt is durable
before product archival begins. Workspace registration and top-level chat
archival have separate durable receipts. An uncertain filesystem effect is never
replayed. After confirmed removal, an explicit recovery action may finish only
the remaining archival steps under the original identities.

The optional catalog `workspaceCleanupCensus` v1 operation returns at most 10,000
indexed identity/location records, a hash of those records, and explicit
`indexed-metadata-only` coverage. It includes invisible rows and refuses overflow;
it reads no transcripts and performs no discovery. Host reconciliation unions
these records with its local mappings, refusing conflicting locations or engines.
This private port does not create a browser path-based deletion API.

Source, installed-owner, composed-browser, and deployed-instance acceptance are
recorded separately. Existing writers or incomplete census coverage prevent
removal; they never produce a partial-success deletion claim.

After a process replacement, metadata settlement validates the original retained
Host and workspace fences plus the completed Native command receipt. This scope
cannot invoke Native maintenance or ordinary Host mutations. Only completed
cleanup with separate chat and workspace archival receipts can release the old
holds into the exact replacement generation; other recovery operations retain
their existing release rules. Uncertain Native removal remains held for inspection.
