## Remaining material differences and release checks

- **Native device experience:** browser notifications and ntfy are available. OS-native notification replies, device synchronization, and STT → agent → TTS fallback remain separate follow-ups.
- **Provider-specific onboarding:** the ChatGPT public device-login integration is implemented; Copilot's installed module requires token or existing SDK authentication. Real account authorization, model catalog connectivity across every provider, and microphone playback still need account/device testing.
- **Release deployment verification:** v0.3.0 is published privately, installed from its exact Git revision, and running locally. The real release checker and isolated update staging both passed; installed HTTP/static assets and settings actions were checked. In-place automatic upgrade/restart is covered by lifecycle fixtures and awaits a subsequent real release. Ecosystem rollback is implemented; app-version recovery uses the recorded previous installation reference.
- **Compatibility boundary:** Unified exposes corresponding host capabilities with its own HTTP/UI and terminal contracts. It does not promise byte-for-byte CLI output, identical shell-completion scripts, or duplication of an active worker's ownership when forking a transcript. The loop-live dependency is pinned to its upstream implementation, including generation correlation and optional host ownership.

Private full-state backups include configuration and saved credentials. They are access-restricted, not encrypted, and remain on the host. Reset previews the selected app-owned directories and retains originals alongside a backup; it does not reset the former CLI's files.

## Verification boundary

The bundle tests include an actual Foundation `load_bundle` round-trip that preserves disabled main and worker tools and embedded root/agent instructions. Setup/registry tests cover scoped writes and inherited overrides, credential redaction, routing shadowing, actual runtime-operation delegation, isolated structural/behavioral module-validation protocol, and login progress/cancellation with a fixture. Core/runtime fixtures cover the module/tool/control behavior. A separate live main-plus-worker run completed six model calls and verified tool hierarchy plus exact per-call and turn usage/cost totals. Real account login and browser audio checks are not implied by fixture success.

The portable export preserves declared module sources and the effective bundle's static instructions/context. It does not export live user messages, project/user dynamic context, credential values, running jobs, or provider SDK internals. The app's pinned live engine is represented by the portable pinned streaming engine in the shared file; Unified reapplies its reviewed live overlay when loading it, and records that conversion as a warning.

Saved portable bundles carry the SemVer build marker `1.0.0+amplifier-unified.snapshot.1`, which Foundation preserves as public bundle metadata. Unified treats that explicit root as a complete snapshot: app behaviors, global module/model/routing defaults, source overrides, and global configurator toggles are not recomposed over it. Credential environment expansion, host filesystem policy, and the mandatory live/app-control integration still apply. Ordinary community roots continue inheriting configured app behaviors and defaults.
