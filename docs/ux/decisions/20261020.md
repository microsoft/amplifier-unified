# October 20 Home and sidebar direction decision

The product owner accepted applying the reviewed vision and contract proposals
to the repository and explicitly authorized a pull request and administrative
merge so the designer could use the shared documents.

## Reviewed source

The proposal is preserved at commit
[`2157b347be3d2a5678fdaaf6c1ea489415c3170b`](https://github.com/microsoft/amplifier-unified/commit/2157b347be3d2a5678fdaaf6c1ea489415c3170b),
against implementation baseline `5da1e1ce137866b780c37d0ebb9a4b63aecfcadc`.
Its four amendment records contain exact before/after wording and target hashes.
The original draft files remain in Git history; current readers use the applied
documents linked from the [review guide](../README.md).

## Accepted changes

- Extend the shared-client vision to cover arrival, retrieval, standalone work,
  and different densities with common meaning.
- Extend client orientation and recognize useful repeated access from independently
  scrolled regions.
- Identify the workspace contract's three sidebar sections as Browse and permit
  the approved Status organization over the same existing work.
- Adopt the eight Home/sidebar promises and retain concrete design and acceptance
  history as implementation notes.
- Use descriptive promise names and ordinary numbering. The draft's abbreviated
  clause labels are unnecessary for the designer's review.

## Corrections requested with acceptance

The same feedback supplied deployed-use screenshots and asked for these fixes:

- Read/unread menu actions must reflect the current chat state.
- Routine background refresh must be silent and preserve layout, including
  Home and both sidebar views.
- Both sidebar views must use consistent chat controls and honor the same
  display preferences, including workspace-name visibility.

These directions are reflected in the new Home/sidebar agreement and the
existing client-feedback and Appearance rules before the fixes are implemented.
Initial loading, actionable failures, and user-initiated operations retain their
meaningful feedback. No permission, session, approval, storage, or inference
authority changes.

## Decision and evidence

**Decision: ratified with edits, October 20, by the product owner.**
The edits are the plain promise names and the corrections listed above.
The user authorized publication and administrative merge of the documentation.
This decision does not establish that the reported runtime defects are fixed or
that the designer has completed a usability review. Those results belong in the
[review evidence](../review.md#evidence-available-and-still-needed).
