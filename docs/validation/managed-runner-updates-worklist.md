# Runner update boundaries

Docker uses the maintained installed DTU Smart Tool and ordinary Smart Tool
package updates. The former Docker qualify/promote worklist, opt-in driver and
isolation certifier are retired. There is no whole-venv inventory or target-local
probe before ordinary Docker execution, stop or removal. Historical accepted
results remain in [managed runner evidence](managed-test-runner.md) and Git;
old unsettled owners, packages and receipts are not reclassified or deleted.

[The current contract](../workspaces/managed-test-runner.md) separates ordinary
Docker package provenance from explicit Incus and registered-machine controller
qualification. The latter retain exact target, engine, source and bytecode
bindings. Their capacity waits stay independent of application updates; a failed
optional tool cannot block a newer app or silently retry when its sequence resumes.

Future work uses the ordinary selected package. Accepted work retains its original
configuration and installation for recovery. Explicit pins remain explicit.
Storage retirement still requires its existing current-use and owner guards;
changing default trust does not authorize cleaning an old unknown environment.
